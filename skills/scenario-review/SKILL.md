---
name: scenario-review
description: Compare stored forecasts for a study and write a decision memo with fresh or frozen totals, cost drivers, timelines, risks and web links.
---

Use `ctf_list_capabilities` to state the environment and organization. Resolve the study with `ctf_list_studies`, then use `ctf_list_scenario_configurations` to obtain scenario ids and configuration ids. They are different identifier kinds. `ctf_list_budget_scenarios` lists the organization's scenarios with their types and lock state.

Read `ctf_get_forecast_readiness` and `ctf_check_scenario_lock`. A locked or archived plan is a valid comparator; it cannot be edited. Call `ctf_compare_study_scenarios` with the study and two to eight scenario ids, requested breakdown dimensions, driver options and optional display currency. Omitted ids select the study's configured planning scenarios. This workflow reads stored results and does not recalculate.

Use returned totals, deltas and drivers. Keep native currencies separate unless the service returns a complete converted total; disclose the FX basis and missing rates. Refuse a decision memo while a non-frozen result is stale. A frozen result remains valid: state its lock and computed_at. Explain structurally different scenarios with identical totals using the service's no_priced_difference result; ask for correction when no explanation is returned.

Write a short recommendation followed by an options table: scenario/type, native total, delta, FPI/LPI/LPO, enrollment duration, sites/countries, budget-cap status and freshness. Explain the leading cost drivers, timeline and enrollment differences, risks and data quality. Distinguish benchmarks from negotiated rates, list unresolved quotes and unchecked cost classes, and include the comparison checksum and returned app_url. Every factual claim comes from returned data or an identified user assumption.

This read-only workflow needs ctf.studies, ctf.scenarios and ctf.planning. If a needed tool is absent, state the missing area. Write workflows can make and recalculate changes through a separate preview/apply cycle with the person's agreement and reason.

Read budget scenario ids from `ctf_list_scenario_configurations`: use each `scenario_id`, not its configuration id. Follow the comparison's top-level `app_url`.

## Links to the web application

Results carry `app_url` values. Each one opens a page of Clinical Trial Forecast for a person signed in to the organization this connection belongs to: a record's `app_url` shows that record, and a result's top-level `app_url` shows the whole result, or the nearest page when the web application has no view of it. `null` means there is no page.

- After answering, give links from those values so the person can open the same data in Clinical Trial Forecast. Label each link with what its page shows, from the table below, for example: Open the cumulative spend chart for ASCEND-1 (Budget and Latest Estimate).
- When the page is only the nearest one (readiness, enrollment), say so, for example: Open ASCEND-1's budget overview.
- Give at most five record links. For more records, give the result's top-level `app_url` instead. For a comparison, a curve, a schedule or a readiness answer, give the top-level `app_url`.
- A comparison link overlays the first 3 compared scenarios; say so when more were compared.
- In a terminal (Claude Code), write the full https:// address as plain text, never in backticks or a code block. Elsewhere a markdown link is fine.
- Use only `app_url` values from results. Never build or edit a link.
- If the page says the link belongs to a workspace the account is not a member of, the person is signed in to the web application with a different account than the one connected here.
- When the person asks for a chart, you may draw one from the result's series, and also give the `app_url` of the maintained view.
